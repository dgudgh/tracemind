# 巡检模板统一契约

更新日期：2026-09-08。

## 原生交付，不依赖导入

内置目录是安装数据，不是客户需要自行导入的示例。SQLite 安装、外置 MySQL 安装和已配置平台的启动流程均初始化同一目录；即使未打开巡检页面、未启用定时任务，也应具备这些模板。所有执行入口复用此目录。

| 原生模板 | 配置检查项 | 说明 |
| --- | ---: | --- |
| Oracle 10g | 72 | 原脚本 53 个数据 SQL 章节 + 19 个健康指标 |
| Oracle Non-CDB | 75 | 原脚本 56 个数据 SQL 章节 + 19 个健康指标 |
| Oracle CDB / PDB | 75 | 原脚本 56 个数据 SQL 章节 + 19 个健康指标 |
| MySQL | 26 | 一个逻辑模板，不按 Shell / PowerShell 拆成两个 |
| PostgreSQL | 19 | 一个逻辑模板 |
| SQL Server | 23 | 一个逻辑模板 |
| 主机（Linux / AIX / HP-UX） | 37 | 保留原 `host_resource` 标识与采集实现 |
| 主机（Windows） | 30 | 20 项可采集，10 项未适配或不适用项目默认停用 |
| 日常标准巡检 | 5 | 辅助组合模板，不替代数据库专属模板 |

普通目录共 9 个模板；数据库还保留 1 个隐藏的旧 `oracle_standard` 兼容记录。检查项、SQL 章节、采集单元和运行返回行数是不同数量，不能互相替代，也不能把“已绑定采集器”表述成“已成功采集”。

Oracle 章节保存原始 SQL、来源文件和行号。`oracle.script:<section>` 精确绑定一个章节；`oracle.query:<metric>` 绑定健康指标采集，不再隐式执行同类脚本章节。复制、编辑和跨部署共享保留这两个来源标识。旧模板的分组标识仍兼容。

内置检查项升级使用目录版本和内容摘要；仅替换与已知出厂内容一致的检查项列表。此前三个 Oracle 变体共有的原始 28 项列表可原位升级，保留 ID、启用状态、阈值、默认配置、实例绑定与执行计划。客户修改过的检查项不覆盖。脚本随程序放入 `backend/scripts`；修改源码不等于旧安装包已更新，正式发布仍需重新构建和现场验收。

## 一个目录，一条执行链

`DBInspectionPolicy` 是模板及策略配置的共同来源。模板页面、一键巡检、小助手批量巡检、定时任务、数据库专用旧巡检接口、AI 触发的巡检，都经由 `inspection.runner.run_inspection` 使用同一个后端解析器。

```text
新建 / 编辑 / 复制 / JSON 或 ZIP 导入
                 |
           模板目录与校验
                 |
 手动 / 小助手 / 定时 / 旧 API / AI
                 |
 execution_policy.resolve_execution_policy
                 |
 确认适用类型和 Oracle 架构 -> 冻结本次配置
                 |
 采集器 -> SQL 与结果证据 -> 统一报告
```

显式选择模板时按技术标识读取最新配置，不替换为其他模板。未指定模板时先匹配用户默认配置，再匹配引擎内置模板，不使用列表第一项或日常模板兜底。停用、不适用、无有效检查项、版本识别失败或连接失败均不得悄悄执行另一份配置。

Oracle 不同架构的自定义默认模板可以并存；`auto` 默认模板适用于所有 Oracle 架构。每个架构只能命中一个有效默认配置。一次执行使用独立配置快照，后续修改从下一次执行生效；报告保留模板标识、修订摘要、实际 Oracle 架构和脚本来源摘要。该快照不等于持久化版本仓库，版本历史/恢复仍属独立待完成工作。

## 来源与适用范围

| 类型 | 内置模板键 | 来源文件 | 执行方式 |
| --- | --- | --- | --- |
| Oracle 10g | `oracle_10g` | `dbcheck10g.sql` | 校验版本后提取数据查询章节 |
| Oracle Non-CDB | `oracle_noncdb` | `dbcheck_noncdb.sql` | 11g 或已确认非 CDB 的 12c+ |
| Oracle CDB/PDB | `oracle_cdb` | `dbcheck_cdb.sql` | 已确认 CDB；结果范围受当前连接容器和权限约束 |
| MySQL | `mysql_standard` | `mysql_check.sh`、`mysql_check.ps1` | 单一逻辑模板，Python 采集器按语义实现 |
| PostgreSQL | `postgresql_standard` | `pg_check.sh`、`pg_check.ps1` | 单一逻辑模板，Python 采集器按语义实现 |
| SQL Server | `sqlserver_standard` | `mssql_check.sh` | 单一逻辑模板，Python 采集器按语义实现 |
| Unix 主机 | `host_resource` | `oscheck.sh` | 沿用主机采集器；各 OS 的实际命令兼容性需现场验收 |
| Windows 主机 | `host_windows` | `oscheck.ps1` | 固定只读 PowerShell 白名单，经现有 SSH 连接采集 |

脚本来源为用户的 `codex/脚本/巡检脚本`，随程序存放在 `backend/scripts`，不能依赖开发机器绝对路径。Shell 和 PowerShell 是参考脚本的平台变体，不按章节编号互换，也不各建一套数据库模板。主机资源与日常组合模板继续保留；不以数据库连接成功证明主机资源、备份或集群信息已采集。

旧 `oracle_standard` 保留原 ID、配置、历史和调度引用，仍可自动检测架构；普通模板选择列表隐藏它，已绑定实例/调度/默认的旧策略仍可管理。注册内置模板不能覆盖现场编辑过的检查项、阈值、默认设置或调度。

## 跨部署共享

- 同一后端：模板修改后各页面刷新目录，所有执行入口直接读取最新配置。
- 不同部署：导出自定义模板 JSON 或 ZIP，在目标平台预览、校验、导入、确认启用。内置模板先复制为自定义模板。
- 固定 Oracle 架构使用格式版本 2。版本 1 的通用模板继续兼容；旧版本平台拒绝格式版本 2，需要升级后导入。
- 保留检查项来源绑定、自定义 SQL、阈值、报告设置、逻辑脚本名称和架构限制；清空现场实例 ID、默认绑定、执行状态和本地脚本路径。
- 目标程序必须具备对应采集器、支持的模板格式及脚本资源。模板文件不是可执行程序，也不会给无关产品自动增加巡检能力。未实现客户现场自动分发、联网同步或离线补丁发布。

## 验证边界

自动化测试覆盖三种 Oracle 匹配、错误/未知架构拒绝、各引擎默认模板、自定义默认配置、旧接口统一入口、配置快照、注册幂等，以及复制后跨独立数据库导入执行选择。

Oracle SQL*Plus 的 HTML/JavaScript 展示代码、环境初始化、PL/SQL 和系统命令不作为数据库健康检查执行。API 模式不是完整 SQL*Plus 报告的逐字复现。Shell/PowerShell 文件用于来源对照，不整体上传执行。

Windows 在线采集要求目标已配置 SSH 与兼容 PowerShell。采集涵盖 OS、CPU、内存、分页文件、磁盘、运行队列、时间、hosts、注册表、计划任务及 Oracle 服务迹象；服务存在不代表 RAC 或数据库健康。权限令牌、外部 OPatch/lsnrctl、Oracle Home 配置定位、SQLPlus 报告及远程文件归档未适配；Unix inode/THP 不能用 Windows 占位值代替。相关项目在内置模板中默认停用，强行启用会校验失败。

Windows 单命令限制 15 秒 / 64 KiB，总采集预算 120 秒 / 512 KiB；平台探测最多两个 10 秒只读命令。连接失败、超时、权限不足或无效结果保持失败证据，不能写成健康。超时关闭 SSH 通道不代表已经确认远程进程退出。

Oracle 10g/11g 还需要兼容的 Oracle 客户端和驱动模式；提供模板和通过模拟测试不代表旧数据库的真实连接验收完成。Windows/macOS 打包以及各数据库、容器、权限组合仍需相应环境验收，不能宣称全部兼容。
