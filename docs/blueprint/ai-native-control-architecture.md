# AI 原生程序与五平衡控制架构

设计更新：2026-10-08。状态：**规划，尚未形成统一控制闭环**。

2026-10-20 补充：[软件四项质量底线](software-quality-contract.md)约束全部 B01-B06 工作包。
AI 不在硬实时控制路径内；控制请求接收与动作停止分别确认；失联时受有限授权和安全点约束。
正确性、人工接管、时延和连续运行需独立验收，不能从本架构文字推导已经满足。

2026-10-20 产品执行边界收敛为[功能卡片与可选 AI 编排](capability-card-orchestration.md)：
功能只能调用登记的已有代码；AI 只选卡片、补参和提出编排，手工入口调用同一内核。
本篇“AI 智能核心”描述可选认知层，不表示基本功能、控制与可用性必须依赖模型。

这是[完整平台蓝图](../../../orchestrator-enterprise/docs/database-operations-blueprint.html)的下一代控制架构，基于用户提出的“AI 即程序、五平衡即控制核心”思想。功能实现现状继续以[当前差距表](current-gap-assessment.md)为准：27 个模块中 7 项主链具备、19 项部分实现、1 项 MES 暂缓。本文不提高既有完成度，不新增 F 编号，不实施 MES 交互。

## 1. 定位与理论边界

平台从“提供功能和工具”向“理解系统、维持目标、受控行动、根据反馈调整”演进。Agent 承担任务协作和执行编排，不等同于整个智能程序体系。

**AI 是可选认知与编排层，五平衡是控制策略；功能卡片绑定已有代码，确定性执行内核拥有最终执行裁决权。**

| 理论视角 | 在本设计中的作用 | 工程载体 |
| --- | --- | --- |
| 系统论 | 定义系统边界、组成、结构和关系 | 资产本体、依赖图、租户/环境边界和执行目标身份 |
| 信息论 | 区分有效证据与未知信息，管理不确定性 | 来源、采样窗口、新鲜度、缺失/冲突标记和证据引用 |
| 控制论 | 根据偏差和反馈实施受限调节 | 目标指标、状态转换、控制预算、反馈窗口和停止条件 |

三者在本架构中形成“定义世界 → 认识世界 → 调节世界”的设计闭环。五平衡是本项目提出的研究与工程分类框架，不是既有行业标准，也不是已经证明收敛或稳定的算法。

“Software 1.0/2.0/3.0”如用于汇报，只表达本文定义的演进叙事，不作为行业统一版本标准。这里的“AI 即程序”不表示模型可以替代事务、权限、校验、执行器和故障恢复代码。

### 理论抽象

`P = (W, G, C, I, B, A, F)`：W 为世界模型，G 为目标，C 为约束，I 为智能，B 为五平衡，A 为行动，F 为反馈。该表达描述设计要素，不是运行时算法或稳定性证明。

## 2. 目标架构

```text
目标与约束：业务目标、硬约束、授权、责任与裁决规则
                            |
AI 智能核心：世界模型、记忆、推理、预测与决策候选
                            |
五平衡控制中枢：资源、调度、管理、动作、反馈
                            |
确定性执行内核：校验、审批、队列、锁、事务、执行与验证
                            |
现实环境：数据库、集群、主机、网络、设备与人
                            |
观测与证据：采集、时间对齐、状态识别、反馈与审计
                            |
          更新世界模型，再评估目标与约束
```

这是对现有部署架构的控制逻辑补充，不要求更换技术栈、重写确认的界面或把各数据库执行引擎合并为一个通用模型。

确定性内核也不是天然安全：它必须通过权限、并发、失败路径和故障注入验收。模型超时、输出无效、证据不足或预算耗尽时，禁止新增高风险动作；已经开始的任务按其确定性停止、补偿或人工接管方案处理。

## 3. 世界模型与自然时间

世界模型不能只是一张资产清单或一段模型描述。拟包含四类信息：

- 对象与关系：资产身份、部署位置、服务端点、角色、依赖和影响范围。
- 当前估计状态：来源、证据 ID、目标指纹、采样时间、状态字典版本、未知/冲突与有效期。
- 历史与记忆：事件、状态转换、已执行动作、验证结果及经审核的经验；隔离租户、环境和敏感原文。
- 可验证预测：候选动作的预期影响、观察窗口、失败假设和适用条件；预测不是已发生事实。

自然时间在工程上表示“事件时间 + 持续时间 + 因果/先后关系”，不定义另一个未验证的物理时间体系。记录 `event_time`、`observed_at`、`ingested_at` 和 `decided_at`，统一时间基准，同时保留源时钟偏差及不确定性。因果关系不能仅凭时间先后认定；过期、缺时钟或顺序冲突的证据不能用于放行高风险操作。

## 4. 五平衡控制契约

每个控制维度都必须定义：观测变量、硬约束、可用动作、调节幅度、反馈窗口和验收条件。平衡不是平均分配，也不能通过一个加权分数抵消安全禁令。

| 控制维度 | 观测与约束 | 调节机制 | 验收条件 |
| --- | --- | --- | --- |
| 资源平衡 | 业务负载、采集成本、内存/IO、存储、网络、模型预算与人员可用性 | 限流、降采样、延期、配额和经授权的并发调整 | 负载上升时保护业务；预算耗尽能降级；不可偷偷扩大预算 |
| 调度平衡 | 优先级、依赖、维护窗口、并发上限、任务租约与目标冲突 | 持久入队、领取、排空、幂等、心跳和失主恢复 | 重启不丢任务；重复请求不重复执行；旧 owner 不产生重复副作用 |
| 管理平衡 | 资产范围、动作权限、审批、责任与策略版本 | 确定性授权、职责分离、授权失效复核和审计 | AI 不能扩权；审批不能绕过硬约束；禁用或撤销能阻止后续动作 |
| 动作平衡 | 影响范围、频率、幅度、冷却期、可逆性和风险级别 | 分批执行、单步预算、预检查、停止条件与受控补偿 | 不反复切换或杀会话；越界拒绝；不可逆动作不得伪称可自动回滚 |
| 反馈平衡 | 新鲜度、缺数、噪声、延迟、验证窗口和独立恢复阈值 | 防抖、滞回、等待反馈、独立结果验证和模型误差记录 | 缺数不当正常；迟到/重复反馈不触发连续干预；持续无改善转人工 |

### 冲突裁决

1. 身份、权限、数据完整性、安全禁令及不可越过的预算是硬门禁；任何一项失败都不能由其他维度的评分补偿。
2. 在硬约束满足后，按已批准的业务目标和 SLO 选择候选；效率、成本与恢复速度的取舍应有版本化策略。
3. 人工审批只放行批准范围内的动作；扩大资产范围、权限或预算需另走授权流程，AI 不能自行修改裁决规则。
4. 多个控制器通过目标锁、持久任务与所有权校验协调；反馈窗口内不重复下发同一干预。外部动作也要有防重与结果核对，不能只在派发时验证租约。
5. 无法识别当前状态、无法证明目标身份、无法安全停止或风险冲突无法裁决时，输出 `blocked` 或转人工，不用低置信度猜测代替门禁。

## 5. 决策、执行与反馈协议

以下为拟议契约，不代表已新增 API、数据库表或通用执行器。

| 对象 | 必需内容 | 目的 |
| --- | --- | --- |
| WorldSnapshot | 目标指纹、状态/关系版本、证据、时间、未知信息与有效期 | 固定决策依据，防止跨实例误用或旧证据放行 |
| GoalSpec / ConstraintSet | 业务指标、允许范围、硬约束、预算、维护窗口、责任人与策略版本 | 区分优化目标与不可违反的条件 |
| DecisionProposal | 候选动作、推理摘要、证据引用、预计影响、五平衡评估、替代方案和失效时间 | 模型只能提出受限候选，不直接持有执行授权 |
| ActionPlan / TaskRun | 目标、审批范围、幂等键、owner/epoch、步骤、预检查、超时、停止/补偿及验证条件 | 复用统一任务和专用执行器，不让模型自由执行命令 |
| FeedbackRecord | 实际动作、观察窗口、来源、前后指标、成功/失败/未知、偏差与报告关联 | 区分执行成功、目标达成和因果归属 |

```text
观测 -> 世界快照 -> 决策候选 -> 控制裁决 -> 审批/预检查
     -> 持久任务 -> 受控执行 -> 等待反馈 -> 独立验证
     -> verified / failed / partial / unknown / manual_required
```

候选可能进入 `blocked`、`expired` 或 `cancelled`，不能默认重试。命令退出码为零不代表业务目标达成；模型自报 confidence 不作为执行许可或已校准风险概率。状态判定依据独立观测和领域验证器，列表、详情、报告与审计共用同一结果。

## 6. 三个演化层次

| 层次 | 能力目标 | 默认开放方式 |
| --- | --- | --- |
| 维持平衡 | 发现偏差、有限纠偏、等待并验证反馈 | 先只读/影子运行，再放行白名单低风险动作 |
| 恢复平衡 | 故障隔离、受控恢复、保护数据并形成结果报告 | 审批、隔离目标、专用执行器和真实恢复验收；不绕过现有阻断 |
| 重构平衡 | 提出资源、拓扑、策略或运行模式优化 | 离线回放/沙箱验证、人工审查、灰度与版本回退；禁止生产中自由探索 |

运行时策略调整、知识更新与模型权重/代码更新分别治理。后两者不能由一次线上反馈直接自动发布，必须进入数据质量评估、独立评测和版本发行流程。

## 7. 建设顺序与现有蓝图映射

现有资产、状态引擎、证据、AI 编排、审批和调度是可复用子能力，不等于五平衡控制中枢已经实现。普通监控/Snapshot 状态桥接、持久巡检 worker、HA 执行桥接和隔离恢复仍按原缺口继续补齐。

| 工作包 | 映射模块 | 当前状态 | 交付及验收目标 |
| --- | --- | --- | --- |
| B01 世界模型与时间语义 | F02/F09/F20/F21 | 规划，有资产/证据/状态子能力 | 统一目标身份、时间、来源与 unknown；过期、冲突和跨实例证据不能放行 |
| B02 目标、约束与冲突裁决 | F07/F18/F26 | 规划，有权限/审批子能力 | 版本化目标与五类约束；硬门禁不可被评分或 AI 输出覆盖 |
| B03 资源与持久调度控制 | F06/F08/F25 | 规划，实际 worker 接线仍缺 | 入队、配额、领取、幂等、取消、所有权及恢复；重启/重入/旧 owner 有验收证据 |
| B04 动作与反馈最小闭环 | F04/F07/F18/F21 | 规划，执行桥接与反馈仍缺 | 一项已支持的低风险动作完成裁决、审批、执行、等待、验证和停止；失败状态端到端一致 |
| B05 受控 AI 决策与独立评测 | F19/F20/F22 | 规划，有诊断编排子能力 | 只读影子运行与盲测；模型不可用、幻觉、无效输出、缺证据时不新增高风险动作 |
| B06 恢复及重构平衡 | F04/F14/F15/F16/F26 | 后续规划，依赖隔离恢复和发行门禁 | 真实恢复、SLO/RTO/RPO、沙箱优化、灰度和回退；不可逆动作单独审批 |

先按[原补齐顺序](current-gap-assessment.md)解决任务、备份恢复、HA 与自动化断点；B01/B02 可做契约设计，B03/B04 必须复用实际闭环，不另起第二套任务系统。所有门禁按能力逐项放行，不因时间到达或文档完成自动进入自主执行。

## 8. 示范案例：复制延迟升高

这是目标演示流程，**未进行本轮实机演练**，不表示平台已支持任意修改数据库或备份参数。

1. 观测：复制延迟升高，同时出现 IO 压力；记录主副角色、实例指纹、采样窗口与备份任务证据。
2. 认识：把“备份占用 IO”作为待验证假设；证据缺失或冲突时继续观察，不直接认定根因。
3. 决策：只有证据与适配器支持时，提出降低某个已授权备份任务并发的候选，而不是立即切换主库。
4. 裁决：核对备份窗口、恢复目标、预算、目标锁和审批；执行器不支持该动作时明确 `unsupported`，不由模型拼命令绕过。
5. 执行：在批准范围内应用一次有限调整，保存原状态与安全停止/补偿方案。
6. 反馈：等待策略定义的观察窗口，再独立核对延迟、IO、备份进度与业务 SLO；不连续补发干预。
7. 结果：改善且证据充分才标记目标达成；恶化则按已验证方案停止/补偿；无改善或反馈未知则保留证据并转人工。
