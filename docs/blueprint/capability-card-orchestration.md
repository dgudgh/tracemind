# 功能卡片与可选 AI 编排

2026-10-23 需求入口更新：客户输入需求后先尝试模型调度；无可用 API 时只打开页面供手动操作。巡检、报告和其他浏览器动作已从自然语言捷径退出，当前实现与验证边界见[客户需求入口](customer-requirement-entry-2026-10-23.md)。本文下列 2026-10-20 盘点保留为历史时点。

设计收敛：2026-10-20。依据用户最新约束：每个卡片对应明确功能，AI 只能编排并调用已有代码；有 AI 时辅助编排，无 AI 时可手动保底。流程、契约与“固定答案”的细化是本设计提案，不代表接口已冻结。本轮是架构收敛与源码入口核对，**尚未完成统一卡片运行时**，不改变 F01-F27 完成度。

用户进一步确认全业务功能也按该方式接入，先生成任务清单再执行。运行前清单、全模块范围、C01-C16 开发任务和验收门槛见[全功能编排任务清单](capability-card-task-plan.md)；当前先编排计划，不实施业务改造。

## 1. 核心边界

**代码实现功能，卡片描述能力，AI 选择与编排，人保有控制权。AI 是可选入口，不是功能执行和平台可用性的前提。**

```text
自然语言 -> 固定意图规则 / 可选 AI -> 卡片或流程候选 --+
                                                  |
手工选择卡片、填表或选择已批准流程 ------------------+
                                                  v
        服务端能力注册表 -> 参数/目标/权限/风险/版本校验
             -> 审批与冻结计划 -> 同一持久任务内核
             -> 已登记代码处理器 -> 事实、规则结论与报告
```

- AI 只能使用服务端登记、当前用户有权使用、目标引擎确实支持的能力及版本。界面上的卡片不等于已经实现的能力。
- 卡片标识、菜单 route_key、UI 展示和实际操作标识分开。打开页面不代表执行功能；同一页面可能包含多个风险不同的操作，不能共用一个含糊的执行许可。
- 只允许服务端白名单中的代码处理器。模型不能提供 handler 路径、任意 URL、脚本、SQL、Shell、Python 或可执行表达式；也不能修改插件、模板、策略代码或自行创建执行能力。
- 用户已有 SQL/脚本模板可由现有受控实现执行，但模型不能在运行时改写脚本填补功能缺口。模板编辑、签发和发行是独立流程，不等于本次编排权限。
- 创建 UI 卡片可以调整标题、布局和默认参数；绑定的能力、风险、权限和可用范围由服务端确定。不能通过改提示词或浏览器存储扩权。

## 2. “固定答案”如何成立

固定的是**功能语义、执行规则、结果结构和受控流程**，不是无论事实如何都输出同一句结论。

| 场景 | 确定性要求 |
| --- | --- |
| 标准业务问题 | 归一化意图命中版本化流程，例如“巡检全部授权数据库”；同一明确意图不因模型临场发挥而更换业务流程 |
| 相同冻结输入、代码/规则版本和证据快照 | 相同业务判断与结果投影；任务号、采样时间等运行元数据单独展示，不承诺任意重采集的字节级相同 |
| 数据、权限、模板或目标状态发生变化 | 如实显示变化，并重新校验；不能为了“固定答案”返回旧事实或固定健康结论 |
| 缺参数、意图含糊或目标不明 | 使用确定的澄清/补参表单，不让模型猜生产目标；没 AI 时同样能手动补齐 |
| 目录中没有或代码尚未支持 | 固定返回 unsupported/blocked 和原因；不由 AI 生成新功能，也不能伪称执行成功 |
| 重复投递同一请求 | 按请求幂等键、目标和参数去重；用户明确重新运行则创建新任务，不能只按问题文本永久去重 |

不能仅靠固定 prompt、temperature 或模型版本保证确定性。标准工作流由代码/配置固定；模型输出只作候选，经服务端验证后冻结为计划。临时组合必须限制步数、依赖、并发、总预算和失败策略；高风险步骤按原审批要求处理。通过审核的组合可以单独版本化，之后作为固定流程复用。

结构化事实、计数、状态、风险规则结论、错误码、证据引用和报告由已有代码计算/渲染，成为权威结果。可选的 AI 解释单独标识来源，不得改写这些字段、补造证据或把假设升级为事实。纯生成解释不纳入“固定答案”的保证；要求固定措辞的正式答复由确定性模板生成。

## 3. 一张卡片的服务端契约

下表为拟议契约，**不是现有 API/schema 已交付声明**。复用现有服务与任务内核，不另建平行执行系统。

| 契约 | 必需内容 |
| --- | --- |
| 能力身份 | card/capability ID、版本、操作语义、服务端处理器映射、配置/实现版本 |
| 真实可用性 | 引擎/目标类型、支持条件、read_only/plan_only/approval_required/blocked/unsupported 等真实边界 |
| 输入与输出 | 结构化 schema、必需参数、类型/范围、结构化前序结果引用；不接受任意表达式或模型拼接命令 |
| 安全控制 | 用户与资产范围、目标指纹、风险、审批、授权有效期及执行前复核 |
| 运行控制 | 幂等键、owner/epoch、超时、有限重试、并发预算、取消/安全点和失败/补偿策略 |
| 人工入口 | 无模型即可使用的参数表单、操作、进度、结果、证据和报告；保留专业功能页面 |
| 权威结果 | 执行状态、采集质量、规则结论、观察窗口、失败原因、报告/证据标识及版本 |

AI 的计划只携带允许的能力 ID/版本、目标引用、参数和步骤依赖，不带可执行代码。校验必须在后端，不能依赖前端过滤或模型自称已获审批。模型只看必要的可用能力描述与脱敏上下文，不接触执行凭据；本地模型也遵守相同边界。

依赖引用按输出 schema 验证，缺失结果、错类型、循环依赖、越界 fan-out 或预算耗尽均按固定策略拒绝/停止。模型不能因为某张卡失败就无限尝试其他写动作。

## 4. 有 AI 与无 AI 的同源执行

| 情况 | 行为 |
| --- | --- |
| 有 AI，命中标准流程 | AI 帮助理解意图与补参；执行仍走固定流程、相同代码和审批 |
| 有 AI，需要临时组合 | 生成结构化候选，显示涉及卡片、目标、参数、顺序、风险和预期输出；经服务端校验及所需确认后执行 |
| 无 AI、超时或输出无效 | 可用手工卡片、专业页面和已批准流程继续工作；不能把普通按钮再转回自然语言解析 |
| AI 中途断开 | 已获授权且不依赖后续模型输出的确定性任务按既定策略继续；需要模型判断的未决步骤转人工，不重复已执行步骤 |
| 人工取消或接管 | 操作同一任务、控制状态与执行器；AI 不得绕过冻结或重新创建等价任务规避取消 |
| 某步骤本来就是纯 AI 解释 | 明确 AI 不可用，展示规则结果/证据或人工分析入口；不能伪造“同等智能效果”或把缺证据标成健康 |

人工保底不是绕过权限、审批或不可执行能力。业务依赖故障时，手动入口也要如实报失败；无 AI 可用不等于目标库、代码或存储不可用时仍能执行。

## 5. 案例：巡检全部数据库

目标流程：选择并冻结当前用户有权巡检的实例集合 -> 按引擎与明确版本选择巡检模板 -> 有界并发执行已有巡检代码 -> 持久化每个任务的结果 -> 规则汇总 -> 已有报告渲染。

- AI 入口：“帮我巡检所有数据库”命中这一固定流程，不能擅自增加备份、参数变更、杀会话或 HA 切换。
- 手工入口：选择“批量巡检”流程/卡片，核对实例范围、模板和参数后运行，调用同一后端工作流。
- 标准结果：目标数、成功/部分/失败/未执行数、真实风险、失败原因、证据与报告链接；连接失败就报失败，缺结论就明确未形成。
- 范围变化、模板升级或授权撤销时按服务端规则重新校验，不把“全部”解释成跨用户、跨环境无限扩展。
- “查询上次结果”与“重新巡检”是不同操作；同一批任务被重复请求时返回原任务，不创建隐藏重复执行。

这是待实现的统一产品路径，不证明当前所有入口、引擎和批量报告都已按此验收。

### 当前巡检已经怎样实现

用户进一步要求核对已有巡检，而不是重写这个已完成的功能。2026-10-20 源码链路为：

1. [诊断入口](../../frontend/src/DiagnosisCenterPage.jsx) `runDiagnosis` 先调用 [resolveAssistantInspectionCommand](../../frontend/src/modules/assistantInspection.js)，明确的“巡检所有数据库”或带执行意图的“巡检当前数据库”先走本地确定性分支，**早于 AI 通用分诊**。
2. `runAssistantInspection` 选择已启用且支持的实例，由 `runAssistantInspectionSequence` 在浏览器逐个执行并汇报进度；未指定模板时把选择交给后端。
3. 小助手与[手工巡检页面](../../frontend/src/InspectionPages.jsx) `runInspect` 共用 [runInspectionTask](../../frontend/src/modules/inspectionApi.js)，不是 AI 生成另一套巡检代码。
4. [巡检 API](../../backend/app/api/v1/inspection.py) `api_run_inspection` 校验实例/显式模板后进入 [dispatch.run_through_queue](../../backend/app/services/inspection/dispatch.py)，再由 [jobs.submit/execute](../../backend/app/services/inspection/jobs.py) 入队、领取并执行。
5. [runner.prepare_findings](../../backend/app/services/inspection/runner.py) 解析执行模板、分派引擎采集、应用阈值并附模板证据；`commit_results` 经过局部 owner/取消/租约与目标检查后持久化结果。
6. [report_builder.build_report_payload](../../backend/app/services/inspection/report_builder.py) 从已保存结果构建模块、风险、建议和报告，明确标记 `analysis_source=rule_engine`。基础巡检与规则报告不依赖模型生成。

由此判断：**已有巡检内核正适合作为能力卡片的第一个正式绑定，不需要重新开发采集、阈值和报告。** AI 的工作是识别用户意图与给出受控参数/计划，手动按钮和 AI 入口都复用该实现。

仍有边界：

- 一部分快速卡片只是填 prompt 或导航；不带明确范围的“巡检数据库”未必命中上述本地分支，会进入后续分诊，应通过明确卡片绑定和补参统一行为。
- 批量目标循环与进度在浏览器，当前已下发的单实例任务持久化，不代表未下发目标和整个批次已有后端恢复能力。刷新/关闭页面后的批次续跑仍需后端批次任务验证。
- `jobs.submit` 在交互请求内执行到终态；已有队列不等于毫秒级接收与后台独立执行已实现。
- 当前 `runInspectWithAi` 只是运行同一 `runInspect` 并展示后续分析提示，不能据按钮名称宣称已经额外调用模型。

本次复跑：前端巡检指令/执行结果用例 20 passed；后端模板分派与报告证据用例 34 passed、7 subtests passed；禁止生产入口绕过队列的 AST 用例 1 passed。均为源码/隔离用例核对，未连接现场数据库或模型，未验证真实权限链和浏览器运行，不作为客户验收。

## 6. 当前入口与落地顺序

2026-10-20 源码抽查：

- [诊断卡片页面](../../frontend/src/DiagnosisCenterPage.jsx) 的 `QuickActionCustomizer` 可编辑 prompt；`selectQuickAction` 对部分卡片导航，其余写入输入框。它是快捷入口，**尚不是统一的强类型功能卡片绑定**。
- [小助手动作](../../frontend/src/modules/assistantActions.js) 的 `executeAssistantActionRequest` 已调用现有 API，有白名单分派基础；仍使用 targetKey 和文字分支，不能把它当作服务端统一计划验证器。
- [运维能力目录](../../backend/app/services/operations_capabilities.py) 已描述部分引擎能力与真实执行边界；它不是覆盖全部业务、带输入输出与执行处理器的完整注册表。
- [巡检派发](../../backend/app/services/inspection/dispatch.py) 与[任务服务](../../backend/app/services/inspection/jobs.py) 可复用；交互仍内联等待终态，异步接收/进度与全平台接管按[质量契约](software-quality-contract.md)继续补齐。

建设顺序：

1. 盘点功能与现有代码/API，区分导航卡、只读操作卡、执行卡和复合流程；未实现能力明确禁用。
2. 在已有能力目录上补齐版本化输入/输出、操作与处理器绑定；手工卡片先直接调用，不依赖 AI。
3. 统一服务端校验、任务、权限、报告和控制；先以一个现有巡检流程验证两种入口同源。
4. 接入只输出结构化计划的可选 AI；标准流程优先，临时组合受限并可审核。
5. 验收同一冻结输入的业务一致性、AI 完全禁用下的手工路径、模型超时/伪造卡片/恶意参数、重复请求、越权、版本变化和运行中接管，之后逐项扩大支持范围。

本轮仅固化设计与入口差距，不修改现有卡片外观或执行行为，不新增 API/迁移，不调用现场模型或数据库，不重启部署。文档完成不能标记为统一卡片引擎已交付。

文档链接/锚点、正文路径、括号平衡、能力目录引用与 diff 格式检查通过；不把引用一致性当作业务闭环或模型效果证明。
