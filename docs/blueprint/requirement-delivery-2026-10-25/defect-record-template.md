# 客户需求执行 缺陷记录模板

每个可复现问题单独一份记录，放入本轮证据目录。下列字段均需填写或说明不适用；本文件是空白模板，不代表已创建或解决缺陷。

| 字段 | 待填写内容 |
| --- | --- |
| 缺陷编号 / 标题 | BUG-日期-序号 / 可观察业务错误 |
| 发现时间 / 发现人 | 时间含时区 / 角色 |
| 严重级别 | S0 / S1 / S2 / S3，定义见测试与发布执行手册 |
| 需求 / 任务 / 用例 | Rxx / Dxx / TCxxx，附 variant_id |
| 环境与制品 | 开发/预生产/现场；前端、API、worker 版本与制品摘要 |
| 平台库与目标库 | 分别填写引擎、版本、合成别名和 schema revision，不填密码或凭据串 |
| 账号与范围 | 角色、授权范围、菜单权限、审批身份；不用登录令牌 |
| 模型 | provider/model/config revision；真实或替身；配置使用受控引用 |
| 前置数据 | fixture ID、时间窗口、预期目标集合、业务真值 |
| 客户原始输入 | 脱敏后的原话、提交时目标、确认/补参内容 |
| 复现步骤 | 从登录/进入页面开始的顺序与必要等待条件 |
| 预期与实际 | 用户可见结果 + 服务端持久证据，不能只贴截图 |
| 请求关联 | 脱敏 request_id / plan_id / batch_id / execution_id / artifact_id |
| 证据 | 网络请求次数、日志、记录摘要、业务真值、截图/制品的本地引用和摘要 |
| 影响范围 | 哪些能力/引擎/路径受影响，是否可能误执行、重复或假成功 |
| 根因 | 定位到具体层和代码；未知时写待定位，不把猜测当结论 |
| 修复 | 变更清单、配置或迁移、修复责任人、提交/候选制品 |
| 复测 | 原用例在修复前/后结果、执行人、时间、证据 |
| 相关回归 | 按影响范围列关联 TC 与真实依赖复验，记录实际结果 |
| 清理与回退 | 测试任务/锁/数据清理结果，是否恢复初始环境 |
| 状态与关闭 | open / triaged / fixing / ready_for_retest / reopened / closed；验收人和关闭理由 |

关闭规则：修复责任人提交 ready_for_retest，由测试确认原问题消失、必要回归通过、实际环境包含修复后才能 closed。无法复现、外部条件阻塞、仅改文案或仅通过 mock 测试，不能直接关闭真实依赖失败。
