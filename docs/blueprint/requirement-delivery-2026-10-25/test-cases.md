状态：全部 `not_run`

适用范围：统一需求入口、模型调度、人工专业页、能力目录、计划/审批/执行、固定流程、批次、报告、迁移发布与审计。

## 1. 需求与判定口径

| ID | 可验收需求 |
| --- | --- |
| R01 | 客户从统一入口输入一句自然语言；只有明确“打开某页面”才仅导航，“查看数据/状态”进入真实只读查询，“重新检查/生成/执行”按各自业务合同进入后续闭环。 |
| R02 | 有已授权模型 API 时先理解意图；模型不可用、低置信或输出无效时准确降级，失败不伪装成功。 |
| R03 | 模型和人工路径只能使用当前用户、目标、引擎和版本可用的已登记能力/固定流程目录。 |
| R04 | “所有/全部”保持完整授权范围并冻结目标集合；不得默认缩成当前实例或单台。 |
| R05 | 缺目标或必填参数时进入补参，保留合法已提取值，并在提交时重新校验。 |
| R06 | 计划、审批、队列、执行、业务结果、报告和回读形成可核对闭环；方案生成不等于实际执行。 |
| R07 | 多步骤只能选择已发布、定版、可校验哈希的固定流程；批量有成员级状态和真实结算。 |
| R08 | 目录、目标、参数、审批、执行与回读均重新鉴权；撤权、越权和审批撤销立即生效。 |
| R09 | 请求幂等、并发认领、断网回查、刷新/重启恢复和迟到回包处理不重放未知副作用。 |
| R10 | 无 API 时打开有权限的专业页或手工表单，用户点击前零执行；页面 GET 不得隐式采集。 |
| R11 | 迁移、制品、前后端版本、启动检查、灰度与回退分别验收；健康 200 不替代 schema/能力就绪。 |
| R12 | 每个结论绑定请求、模型/目录版本、冻结目标、执行编号、时间窗、业务真值与不可变证据。 |

## 2. 层级、优先级和共享夹具

- **L1**：纯模块/合同测试，可使用 mock；不证明 HTTP、浏览器、真实 MySQL 或真实模型。
- **L2**：真实 HTTP 服务 + 独立 MySQL 控制库；允许确定性模型 stub。验证事务、鉴权、队列和证据合同。
- **L3**：真实浏览器 + 独立 MySQL 控制库；允许模型 stub，仅验证 UI 与真实 HTTP 协作，不计作真实模型验收。
- **L4**：已明确授权的真实模型 + 真实 MySQL 目标/独立受控目标。目标引擎禁止替换；任何实际副作用需审批或隔离环境。mock、stub、SQLite 和 Oracle 替代结果均不得计入 L4。
- **P0**：最先执行的发布阻断；**P1**：随后执行的交付阻断；**P2**：顺序靠后，但只要场景适用仍是完整需求交付的必测门禁，不能因优先级较低而跳过或记为通过。

共享合成夹具：`mysql-a`、`mysql-b` 为当前账号授权 MySQL 目标，`mysql-c` 为越权 MySQL 目标，`oracle-a`、`oracle-b` 为授权 Oracle 目标，`pg-a` 为授权 PostgreSQL 目标；在 `mysql-a` 与 `mysql-b` 各建一个同名数据库 `app_same`，分别写入不同 `target_marker`，并为已登记的 `performance.lock.read` 准备可区分的受控锁等待签名 `lock_target_a`、`lock_target_b`。`target_marker` 只供独立测试夹具核对连接身份，不作为自然语言入口可生成或执行任意 SQL 的能力。`U-requester` 为请求人，`U-approver` 为独立审批人，`U-limited` 只可见 `mysql-a`。测试数据只含合成名称与合成行。

共享计数基线 `B0`：执行前记录 dispatch receipt、模型调用、plan、approval、queue、effect receipt、report、artifact、collector invocation 和目标业务真值行数。共享清理规则 `C0`：先按 test_run_id 导出证据，再取消未开始计划/批次；等待已开始任务到可确认终态，禁止直接删除在途证据；删除独立测试 schema/合成制品，恢复权限与模型 stub；保留脱敏审计索引。涉及真实模型的请求文本、重复次数和外发字段需事先获批；涉及实际执行的用例只能在独立目标或另行批准的真实目标运行。

证据包最低内容：`case.json`（输入、请求号、版本和断言）、脱敏 HAR、关键页面截图/录屏、服务端相关日志、按 test_run_id 导出的持久记录、业务真值前后快照及摘要。证据路径均为未来执行时的建议结构 `reports/requirement-delivery-2026-10-25/<TC号>/`，当前未创建。文中“自动化”均为**待开发**测试，不把不存在的脚本或命令描述为现成能力。

## 3. 入口与目录（TC001—TC008）

### TC001 一句话执行意图进入统一入口

- **对应需求 / 层级 / 优先级 / 状态**：R01、R03；L3；P0；`not_run`。
- **前置数据**：`U-requester` 已登录并选中 `mysql-a`；启用确定性模型 stub；记录 B0。
- **实际输入与步骤**：输入“检查 mysql-a 当前的锁等待并给我结果”；单击提交一次；观察请求、工作区和任务区。
- **业务可观察预期**：只出现一个统一需求任务；显示识别出的已登记当前锁等待读取能力和 MySQL 目标，不臆造“最近一小时”能力，不跳到 Oracle 页面，不出现第二套分诊。
- **后端可核对断言**：仅一次 `/assistant/dispatch-intent`；目录快照只含授权 MySQL 能力；产生一个 request_id，并按读取合同关联同一 direct result 或只读计划，输入哈希一致；不得隐式创建异步采集/sync 任务。
- **证据要求**：HAR、入口与任务区截图、dispatch 与 direct-result/plan 引用、异步任务计数、目录快照摘要。
- **清理方式**：C0；若合同使用只读计划且尚未执行则取消并保留取消审计。

### TC006 目录版本在计划中冻结

### TC007 两个同名数据库目录身份不混淆

- **对应需求 / 层级 / 优先级 / 状态**：R03、R12；L2；P0；`not_run`。
- **前置数据**：`mysql-a/app_same` marker=`A`、锁签名 `lock_target_a`，`mysql-b/app_same` marker=`B`、锁签名 `lock_target_b`；两目标均授权；`performance.lock.read` 已登记。

- **业务可观察预期**：页头、计划和结果始终显示 `mysql-b/app_same`，已登记锁等待读取结果只包含 `lock_target_b`，不提供任意 SQL 输入。
- **后端可核对断言**：能力为 `performance.lock.read`；冻结 target_id/connection fingerprint 指向 mysql-b；领域证据含 `lock_target_b`；独立夹具 marker=B；无 mysql-a 能力调用记录。
- **证据要求**：目标清单、能力/连接审计、受控锁等待真值、独立 marker 核对与页面截图。
- **清理方式**：C0，保留共享 fixture。

- **清理方式**：恢复权限，C0。

## 4. 模型理解、输出与降级（TC009—TC020）

### TC009 真实模型准确选择 MySQL 锁等待能力

- **对应需求 / 层级 / 优先级 / 状态**：R02、R03；L4；P0；`not_run`。
- **前置数据**：获得真实模型外发授权；只发送合成目标名和目录 schema；`mysql-a` 为隔离真实 MySQL，锁等待能力已放行且只读。
- **实际输入与步骤**：输入“看一下 mysql-a 现在有没有锁等待”；执行一次并回读。
- **业务可观察预期**：选择 MySQL 锁等待能力，显示真实结果或明确无证据，不跳转 Oracle。
- **后端可核对断言**：保存 provider/model/revision、原始结构结果的脱敏摘要、目标 fingerprint；业务查询确实发往 mysql-a。
- **证据要求**：授权记录、模型回执、连接审计、业务真值和页面结果。
- **清理方式**：只读，无目标变更；按 C0 保留审计。

### TC010 真实模型报告请求重复运行的稳定性

- **对应需求 / 层级 / 优先级 / 状态**：R02、R12；L4；P0；`not_run`。
- **前置数据**：明确批准向真实模型发送同一合成需求多次；`mysql-a` 独立证据集固定；报告执行仍需审批。
- **实际输入与步骤**：用不同 request_id 连续提交 5 次“生成 mysql-a 最近 7 天售后报告”，只比较理解结果，不审批执行。
- **业务可观察预期**：5 次均显示报告能力和 168 小时时间窗；任一次无效输出都明确失败，不用成功样本掩盖。
- **后端可核对断言**：5 个独立模型调用与回执；逐次记录 reason/params/provider revision；report/artifact 计数保持 B0。
- **证据要求**：重复运行授权、5 次结构结果、成功率与失败样本、零执行计数。
- **清理方式**：取消 5 个待审批计划，C0。

### TC011 真实模型 invalid_output 缺陷复验与非法响应负向变体

- **对应需求 / 层级 / 优先级 / 状态**：R02；L4 主项 + L2 强制负向变体；P0；`not_run`。
- **前置数据**：获批真实模型诊断；使用 2026-10-23 曾触发 `invalid_output` 的同一类合成报告请求和已修复候选版本；另准备一个只在 L2 返回非法结构的模型 stub；禁止记录密钥和完整敏感 prompt。
- **实际输入与步骤**：L4 主项向获准真实 provider 提交原失败请求并回查；确认能进入正确报告能力的参数/确认/审批流程但不批准实际执行。随后在 L2 使用新 request_id 注入非法响应，核对安全降级。
- **业务可观察预期**：L4 主项必须产生通过严格 schema 的合法选择并进入应有报告流程，若仍为 `invalid_output` 则本用例失败；审批前不生成报告。L2 负向变体显示“模型输出无效，已转人工”，不显示报告完成。
- **后端可核对断言**：L4 保存真实 provider/model/revision、合法结构和计划/确认引用，queue/report/artifact 在未审批时不增加；L2 reason=`invalid_output`，仅记录字段路径、错误类型和脱敏摘要，无 plan 执行、queue、report 或 artifact。
- **证据要求**：真实外发授权、原缺陷关联、L4 合法结构/流程记录、L2 脱敏 ValidationError、两套独立 request_id 与 B0 对比；不得用 L2 代替 L4 通过。
- **清理方式**：取消 L4 待审批计划，释放 stub，执行 C0。

### TC012 模型超时不切换模型重派

- **对应需求 / 层级 / 优先级 / 状态**：R02、R09；L2；P0；`not_run`。
- **前置数据**：模型 stub 超过入口截止时间才返回合法选择；配置第二 provider 但不允许 failover。
- **实际输入与步骤**：提交“列出 mysql-a 巡检任务”；等待超时，再等待迟到响应。
- **业务可观察预期**：及时显示超时并进入人工路径；迟到模型结果不覆盖页面，也不出现第二次处理。
- **后端可核对断言**：一次 provider 调用；reason=`ai_unavailable/timeout`；迟到结果被丢弃；无 plan。
- **证据要求**：客户端/服务端时间线、provider 调用计数、回执与 plan 计数。
- **清理方式**：停止延迟 stub，C0。

- **实际输入与步骤**：提交“帮我看看最近情况”；打开降级后的手工表单。

- **证据要求**：结构输出、阈值配置、页面截图、计数对比。
- **清理方式**：C0。

### TC014 模型预算耗尽准确提示

- **对应需求 / 层级 / 优先级 / 状态**：R02、R12；L2；P1；`not_run`。
- **前置数据**：将合成账号的入口预算设为已耗尽；模型 stub 可用但不应调用。
- **实际输入与步骤**：提交一个可识别报告需求并打开人工页。
- **业务可观察预期**：提示预算耗尽并允许人工继续；不说“未配置 API”或“处理成功”。

- **后端可核对断言**：两个唯一 member/plan/execution；批次计数等于成员终态聚合；无第三目标。

### TC058 批量部分失败不得结算全部成功

### TC059 批量成员 0 条与失败分别汇总

## 10. 并发、断网与恢复（TC075—TC086）

### TC075 同 request_id 并发只调用一次模型

### TC076 不同 request_id 的相同输入是两个独立请求

### TC077 同 request_id 不同输入冲突拒绝

### TC078 客户端丢失 POST 回包后找回效果计划或只读结果

- **对应需求 / 层级 / 优先级 / 状态**：R09；L3；P0；`not_run`。
- **前置数据**：浏览器在发送前持久保存 request_id；准备 A（效果计划待确认）和 B（通过既有持久计划完成的已存结果读取）两个强制变体；代理可分别丢弃响应。

- **清理方式**：卸载隔离候选或销毁临时环境；不改当前运行服务。

### TC107 升级后关键闭环烟测

- **对应需求 / 层级 / 优先级 / 状态**：R06、R11、R12；L4；P0；`not_run`。
- **前置数据**：仅在获批预生产/隔离环境完成迁移并启动同版本前后端；真实模型和真实 mysql-a 已授权；报告实际执行获审批。
- **实际输入与步骤**：先做真实模型只读查询；再创建、审批、执行一个合成报告；下载并核对真值。
- **业务可观察预期**：两条链路均绑定正确 MySQL；报告结果与合成真值一致；任一失败则发布不通过。
- **后端可核对断言**：模型回执、plan、approval、queue、execution、effect receipt、report/artifact 全链齐全且版本一致。
- **证据要求**：所有授权、全链导出、真值、下载 hash、浏览器录屏。
- **清理方式**：删除合成目标数据/制品，保留脱敏发布证据，C0。

### TC108 灰度禁用模型时人工路径仍可用

- **对应需求 / 层级 / 优先级 / 状态**：R10、R11；L3；P0；`not_run`。
- **前置数据**：候选环境；模型调度 feature flag 关闭，专业页和计划内核开启。
- **实际输入与步骤**：提交报告需求；手工填写并停在审批前。
- **业务可观察预期**：人工路径完整可达，无模型调用；不因关闭自动调度而使专业页不可用。
- **后端可核对断言**：provider 调用 0；手工提交生成一个待审批 plan；无自动执行。
- **证据要求**：flag、HAR、provider/plan 计数、页面。
- **清理方式**：取消计划，恢复 flag，C0。

### TC109 回退保留历史任务与结果

- **对应需求 / 层级 / 优先级 / 状态**：R09、R11、R12；L2；P0；`not_run`。
- **前置数据**：候选版本已有成功历史结果和一个在途任务；准备兼容的旧应用版本；数据库禁止删表式回退。
- **实际输入与步骤**：按回退流程禁用新调度、切回旧应用；回读历史记录并核对在途任务。
- **业务可观察预期**：历史结果不被删除；在途显示待核对/受限，不自动重放；专业页可按兼容矩阵使用。
- **后端可核对断言**：receipt/report 数据仍在且 checksum 不变；无新副作用；回退日志记录版本。
- **证据要求**：回退前后版本、数据 checksum、在途任务审计与页面。
- **清理方式**：销毁隔离回退环境或按计划恢复候选版本。

### TC110 实际运行进程必须加载候选版本

- **对应需求 / 层级 / 优先级 / 状态**：R11、R12；L3；P0；`not_run`。
- **前置数据**：准备候选版本标识与预期进程启动时间；存在旧进程替代风险。
- **实际输入与步骤**：部署/重启获批后，读取监听进程、工作目录、版本端点、schema revision；浏览器执行兼容探针。
- **业务可观察预期**：页面显示的版本与候选一致；若仍为旧进程则发布失败，不能因 HTTP 200 通过。
- **后端可核对断言**：PID/启动时间/commit/digest/schema revision 四者绑定本次发布；能力探针来自该进程。
- **证据要求**：部署授权、进程快照、版本/迁移响应、浏览器 HAR。
- **清理方式**：按发布窗口保持或回退；测试合成数据按 C0 清除。

## 13. 性能与审计（TC111—TC116）

以下数值是**拟定验收预算**，用于未来压测/演练的通过阈值；当前没有执行数据，不表示已达标。若产品 SLO 后续正式发布，应以批准后的 SLO 替换并保留变更记录。

### TC111 目录与调度 HTTP 延迟预算

- **对应需求 / 层级 / 优先级 / 状态**：R02、R03、R12；L2；P1；`not_run`。
- **前置数据**：独立 MySQL 含 500 张可见/不可见合成卡；模型 stub 固定 100ms；预热后运行 200 次、并发 10。
- **实际输入与步骤**：混合执行目录读取与 dispatch，记录端到端及剔除模型后的服务端耗时。
- **业务可观察预期**：拟定预算：目录 p95≤500ms，stub 调度 p95≤1.5s，错误率≤1%；超预算明确失败。
- **后端可核对断言**：每请求唯一 receipt；无丢失/重复 plan；延迟分解含 DB、目录、provider。
- **证据要求**：待开发压测工具版本、原始样本、分位数计算、资源曲线和实体计数。
- **清理方式**：删除压测用户/卡片/回执，C0。

### TC112 全量目标解析规模预算

- **对应需求 / 层级 / 优先级 / 状态**：R04、R12；L2；P1；`not_run`。
- **前置数据**：合成 1000 个资产，其中 600 授权、300 越权、100 禁用，多引擎分布固定。
- **实际输入与步骤**：执行 100 次“全部 MySQL/全部数据库”范围解析，不启动任务。
- **业务可观察预期**：拟定预算：p95≤1s；每次页面/响应的纳入、拒绝、不支持数量稳定且总数守恒。
- **后端可核对断言**：冻结集合 hash 可复算；无越权 target_id；查询次数无明显 N+1（阈值由实现评审确定并记录）。
- **证据要求**：资产生成清单、延迟样本、查询统计、集合校验。
- **清理方式**：删除合成资产与权限，C0。

### TC113 同键并发认领容量预算

- **对应需求 / 层级 / 优先级 / 状态**：R09、R12；L2；P0；`not_run`。
- **前置数据**：独立 MySQL；模型 stub 带调用计数；同一 request_id 并发 100。
- **实际输入与步骤**：同时发起 100 个完全相同请求；等待所有响应并回查最终回执。
- **业务可观察预期**：拟定预算：所有请求 10s 内得到处理中或最终结果；用户只看到一个任务。
- **后端可核对断言**：模型调用=1、claim=1、receipt=1、plan≤1；无死锁/唯一键未处理错误。
- **证据要求**：待开发并发工具、全部响应、数据库锁/错误日志、实体计数。
- **清理方式**：取消计划，删除压测回执，C0。

### TC114 不同请求并发吞吐预算

- **对应需求 / 层级 / 优先级 / 状态**：R09、R12；L2；P1；`not_run`。
- **前置数据**：100 个用户或等价隔离身份，各自唯一 request_id；stub 固定响应；只到确认态。
- **实际输入与步骤**：并发 100 个请求，统计响应、回执和计划。
- **业务可观察预期**：拟定预算：p95≤3s、错误率≤1%；每个请求显示自身任务，不串单。
- **后端可核对断言**：模型调用、receipt、plan 都为 100；request_id/input_hash/actor 一一对应，无跨用户泄漏。
- **证据要求**：负载定义、原始响应、分位数、映射核对和资源曲线。
- **清理方式**：批量取消计划并删除合成身份/数据，C0。

### TC115 审计完整性与敏感信息检查

- **对应需求 / 层级 / 优先级 / 状态**：R08、R12；L2；P0；`not_run`。
- **前置数据**：准备成功、invalid_output、403、审批撤销、执行失败、0 条成功六类合成请求。
- **实际输入与步骤**：逐类执行到规定终态；导出审计并扫描密钥、密码、完整连接串和未脱敏 prompt。
- **业务可观察预期**：管理员能按 request_id 还原决策链；普通用户只见自身允许内容；界面无秘密信息。
- **后端可核对断言**：六类均含 actor、request/input hash、provider/version（适用时）、能力/目标/参数 hash、状态时间线和证据引用；秘密扫描 0 命中。
- **证据要求**：六条审计包、字段完整率、权限回读结果、敏感扫描报告。
- **清理方式**：删除合成业务数据；保留按策略脱敏的审计样本，C0。

### TC116 报告与审计留存查询预算

- **对应需求 / 层级 / 优先级 / 状态**：R06、R12；L2；P2；`not_run`。
- **前置数据**：独立 MySQL 写入 100 万条合成审计索引和 10 万份合成报告元数据，不写大正文；建立候选索引。
- **实际输入与步骤**：按 request_id 精确查、按用户+7天分页查、按 artifact UID 查，各执行 100 次冷暖混合查询。
- **业务可观察预期**：拟定预算：精确查 p95≤300ms，7 天分页 p95≤1s，页面不超时且总数正确。
- **后端可核对断言**：结果归属/权限正确，无全表错误扫描或重复记录；执行计划使用预期索引，资源峰值被记录。
- **证据要求**：数据生成规则、查询计划、原始时延、分位数、结果计数和资源曲线。
- **清理方式**：删除整套独立压测 schema；保留脱敏汇总，不保留百万级临时数据。

执行顺序建议按证据强度推进：L1 合同 → L2 HTTP/MySQL → L3 浏览器 → 获批后的 L4。L1/L2/L3 通过不能替代 L4；真实模型理解通过也不能替代真实业务执行，真实执行必须另有审批或使用隔离目标。每条适用用例（包括 P2 和性能/审计用例）只在其“业务可观察预期”和“后端可核对断言”同时满足、证据包完整且清理完成后才可从 `not_run` 改为 `passed`。P0/P1/P2 只决定执行顺序，不改变适用用例的必测性质；任何跳过、环境不具备或授权缺失应记 `blocked/not_run` 并保留原因，不得写成 passed。
