# batch-3 首片：执行前复核与冻结完整性

日期：2026-10-20。接续 T05，不做 MES、不增加采集/写处理器、不开放批准或接管，不迁移或重启真实平台。保留工作区并行修改。

## 范围与理由

1. 新增只读的计划复核入口，返回当前校验结论、拒绝码与复核时间，不调用业务处理器、不创建计划/修订/审批记录。
2. 创建、校验和实际执行共用参数/依赖预算检查；实际执行继续逐步重查权限、资产身份、版本与停用，复核结果不是可复用的授权票据。
3. 审批是否需要由冻结能力种类推导，不能仅相信可变的 `approval_state`。本片仍不接受 pending/approved 放行，不开放会话终止。
4. 冻结快照、修订副本与步骤投影在读取/执行前检查结构和一致性；损坏数据明确冲突拒绝，不产生 HTTP 500 或带病执行。
5. 现有居中结果弹窗增加人工“执行前复核”，不依赖 AI，不改既有按钮与视觉体系，不把复核通过当执行完成。

## 合同

- 已接源码：`GET /api/v1/assistant/plans/{plan_id}/validation`，复用现有会话及 `asset.read` 路由底线；服务层按实际业务权限/资产范围授权，其他用户不可见，admin 只能查看他人复核而不能代执行。实际验证状态见[执行记录](../archive/acceptance/2026-10-20-plan-validation-u03.md)。
- 响应 `capability.plan_validation/v1`：`plan_id`、`revision=1`、`checked_at`（UTC）、`plan_status`、`can_execute`、`issues=[{code}]`、`approval_available=false`、`requires_recheck=true`。失败码只给受控标识，不回显凭据/参数/连接串。
- 可执行仅指本时点的三个已接线读取；执行仍从原执行入口重查，复核不产生批准或租约。不接受请求参数、任意处理器或扩范围。
- 既有六条 API 保持原输入/输出语义；OpenAPI 只增此 operation，不更新数据库或其他基线。

## 验收计划

- 隔离库：复核前后所有相关行/审计计数与状态一致，业务处理器零调用；成功/停用/撤权/版本变化/目标更换/缺参/已结束/他人计划逐项核对。
- 冻结缺陷：损坏 definitions/steps/修订副本、伪装审批 not_required 均拒绝；参数与 DAG/预算复查有定向断言；历史有效快照不因后续版本升级无法读取。
- HTTP：实际会话与 AuthMiddleware；无身份、跨账号、范围失败和损坏快照保留正确错误码；七条路由精确映射，无通配授权。
- 前端：共享 API 合同、损坏/超时响应拒绝；旧复核不覆盖新清单，不改变原计划成功状态，不自动执行。
- Chrome：手工创建/执行后回读，复核前后零业务 POST，失败显示真实拒绝，桌面/手机与原流程回归。
- 独立审查最终差异；构建、前端集、相关后端回归与 fast 门禁分别记录，不用数量代替现场验收。
