# 客户需求入口：模型调度与手工页面

验证日期：2026-10-23。适用于本工作区的需求输入框；不代表已部署或客户现场验收。

用户确认的流程：客户写出需求，先使用已配置的大模型 API 理解意思，再调用后台已经登记的能力卡片；没有 API 时打开对应页面，让客户自行点击。

后续实施与验收按[详细任务计划 RQ01—RQ20](customer-requirement-task-plan-2026-10-23.md)推进，已实现的基础与待补齐/待实测项分开记录。

## 实现

```text
需求输入 -> /assistant/dispatch-intent
  有可用模型 -> 当前用户/实例可用的能力目录 -> 模型选择能力和参数
              -> 服务端重新校验 -> 已保存计划与执行结果/确认审批
  无模型、不可用、未匹配 -> 本地匹配功能页面 -> 用户手动操作
  无明确页面匹配 -> 手动能力清单
```

- [需求入口](../../frontend/src/DiagnosisCenterPage.jsx) 统一使用 [resolveCustomerRequirement](../../frontend/src/modules/assistantRequirement.js)。巡检、报告生成和旧浏览器动作不再早于模型调度，也不再在模型降级后自动执行。没有再调用第二套 AI 分诊。
- [后台调度](../../backend/app/services/capability_dispatch.py) 每次固定默认或首个启用的 provider，按实例引擎和当前账号过滤目录，将完整参数约束交给模型。只接受登记的能力及类型化参数，模型不能创造 SQL、脚本或处理器。
- 模型输出无效、低置信、预算耗尽或服务不可用时转人工；计划创建或执行出错时保留真实错误，禁止换模型再次派发。接口沿用请求大小、重复 JSON 键、身份、资产范围和计划错误边界。
- 只读能力通过服务端计划执行；其他能力创建计划，继续沿用现有确认和审批。缺实例时打开所选能力的补参表单。权限、版本、目标和风险仍由服务端判断。
- 本地匹配只决定页面，不能触发采集、巡检、报告生成或诊断副作用。报告、巡检和慢 SQL 的实际菜单匹配有用例覆盖。
- 连接中断时提示先核对任务清单，不重复请求；权限、参数和执行错误不伪装成“没有 API”。切换实例、登录状态或打开/关闭清单后忽略迟到响应。
- 原“自动生成工单/通知售后群”选项依赖已移除的本地诊断捷径，入口不再展示该无效选项；历史诊断详情页保留原有操作。

当前模型调度协议一次选择一张能力。跨多张卡片的任意组合不由本次接口承诺；已有流程库继续按其自身合同使用。
