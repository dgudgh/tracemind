# 软件四项质量底线与验收契约

确认日期：2026-10-20。适用：mesdbtools 平台、任务执行端及后续 AI 控制能力；MES 交互仍暂缓。

用户要求：**不能出错；必须可控，人必须随时可以接管；毫秒级响应；7×24 小时运行，不能崩溃。**

这四条是架构与发布的约束，不是功能完成声明。下文具体时延、可用率和恢复时间是**建议验收草案，尚未冻结或实测**；不能把写文档、测试通过、进程存活当作达标。不能证明任意输入下软件绝不出错或单进程永不退出，必须同时建设预防、检测、隔离、安全停止与恢复机制，不用“自动重启”替代业务正确性。

## 1. 四项要求的工程含义

| 编号 | 用户要求 | 必须守住的底线 | 不接受的替代说法 |
| --- | --- | --- | --- |
| Q01 | 不能出错 | 错误目标、越权、重复副作用、数据破坏及虚假成功必须被阻断；无法判断时明确 unknown/blocked/failed | 没报异常就是成功；AI 的高置信度就是事实；连接失败也生成健康报告 |
| Q02 | 随时可接管 | 有权限的人可撤销自动执行权、冻结新动作、查看在途动作和确认停止结果；失联后执行端受有限授权约束 | 点了取消就当作停止；停掉页面或 API 进程就代表远端命令已结束 |
| Q03 | 毫秒级响应 | 控制与交互快速反馈，耗时工作持久入队；接收、排队、执行、完成分别计时 | 把巡检、恢复、模型推理塞在同步请求里；用平均值遮住长尾或失败 |
| Q04 | 7×24 稳定运行 | 单组件故障被隔离，服务与任务能恢复；已确认的任务、控制指令和证据不静默丢失 | 配置 restart 就宣称高可用；重启后重复执行危险动作；健康页 200 就代表业务可用 |

四项必须同时成立：不能为了时延跳过鉴权、审计和持久化，也不能为了“不断服”在控制状态未知时继续高风险操作。失去安全前提时拒绝写动作属于正确保护，但不能因此把该动作的可用性统计成成功。

## 2. 正确性与确定性内核

AI 提出假设和计划，确定性内核决定是否允许执行；本地模型与远端模型使用同样的权限、证据和动作边界。

- 每次执行绑定不可歧义的目标身份、资产范围、参数摘要、模板/策略版本和授权有效期；名称、IP 或一段自然语言不能单独充当身份。
- 证据缺失、过期、冲突、采集失败与反证不能被包装成支持结论。执行成功、结果完整、诊断成立和业务恢复是不同状态，列表、详情、报告共用权威结果。
- 并发请求使用幂等键与条件提交；owner/epoch 校验覆盖副作用前和结果提交点。外部系统不支持 fencing 时，依靠专用适配器、操作标识和对账收窄保证，不宣称通用 exactly-once。
- 超时或断网导致外部动作结果不明时，标记待核对，先查询目标实际状态；不能自动当失败重做，也不能先标成功。
- 不可逆动作单独审批，危险能力未通过其目标引擎验收前保持 blocked/只读方案。补偿可能有副作用，不把“有回滚脚本”当作可安全回滚的证明。
- 审计与业务状态应原子记录；外部动作采用意图记录、可核对操作标识及结果对账。审计或控制持久化失败时阻止新增高风险动作，不能故障降级为无审计执行。

验收反例至少覆盖：错误实例、权限撤销、模板变更、重复请求、迟到旧 owner、并发取消、空证据、模型无效输出、提交失败、外部已执行但回报丢失。存在未关闭的相关 S1 缺陷或关键证据缺口时，不放行对应自动执行能力。

## 3. 人工接管与安全停止

### 控制权

拟统一到资产/任务范围的控制模式：只读观察、建议、审批后自动执行、人工接管、冻结。控制权变更持久保存操作人、范围、原因、版本和有效期；进程重启、租约换主或模型建议不能自行解除人工接管/冻结。

1. **冻结**：先撤销该范围的新动作许可，再处理在途任务；只读观察默认保留，但仍受采集开销和数据权限约束。
2. **暂停**：仅在执行器声明并验证过的安全点暂停。没有可验证安全点的适配器不得宣称支持暂停续跑。
3. **取消**：传播取消请求、撤销后续步骤许可并核对执行端结果；请求成功不等于动作已经停止。
4. **人工接管**：提升控制 epoch，拒绝旧计划和旧 owner 的后续提交/下发，交接目标现状、已执行步骤、未知结果与风险；人在授权范围内操作，不能被后台 AI 抢回控制。
5. **恢复自动**：显式授权，重新预检查目标、权限、版本和业务状态；不得原样恢复过期计划或依赖旧证据。

控制接口保留独立的容量与优先级，不排在 AI、巡检、报告生成或普通重试队列后面。接管/冻结不依赖模型可用，鉴权和审计仍不可省略。

### 停止协议

显示并区分：`请求已持久记录 -> 待执行器确认 -> 已停止/已到安全点 -> 需要人工处理`。无法立即中断的数据库调用、已提交事务或已完成外部动作，必须显示实际阶段，不能强杀后假称已回滚。

在线、可中断动作的停止确认单独设时延目标；授权失联时执行端依靠本地有效期与安全点约束停止继续扩展副作用。最坏停止时间预算为 `剩余授权有效期 + 控制检查间隔 + 到达安全点时间`，三项都必须有已验证上界；授权有效期用本地单调计时和有界时钟误差处理，不能让系统时间回拨无限延长许可。

网络分区时不能承诺远端“立刻收到按钮”；必须显示失联/停止未确认，阻止新高风险动作，并提供经过认证和审计的现场接管通道。适配器无法给出有限停止边界时，不进入自主执行白名单。平台、Agent 与操作系统均失效时还需现场/带外操作手册，不能只依赖同一个 Web 页面。

## 4. 毫秒级响应预算

下表是**建议值，未验收，不是当前性能**。仅在版本、硬件、拓扑、数据量、并发/请求分布、网络 RTT、缓存状态与依赖健康均冻结的负载包下评估，不能通过缩小样本或跳过安全门禁达标。

| 路径 | 建议 P95 / P99 | 测量边界与结果 |
| --- | --- | --- |
| 页面本地操作反馈 | 50 / 100 ms | 用户事件到首个可见处理状态；本地反馈不能显示尚未得到服务端确认的“已接收” |
| 普通分页读取 | 200 / 500 ms | 服务端收到请求到完整响应，包含鉴权和平台库查询；页面端到端另记网络、渲染时间；实时目标库查询另列 |
| 长任务接收、接管/冻结请求确认 | 100 / 300 ms | 包含鉴权、门禁及任务/控制意图持久化，返回标识；不代表任务完成或执行器已停 |
| 在线、可中断适配器确认停止 | 目标 P99 <= 500 ms | 从控制请求持久化到执行器确认并完成安全停止校验，**包含投递时间**；需网络/适配器准入，不套用于不可中断操作 |
| 断网或不可立即中断操作 | 单独冻结有界停止预算 | 必须公开剩余授权、检查间隔及安全点上界；不能放在上一行被统计隐藏，也不能宣称毫秒级停止 |

巡检、备份恢复、AWR、现场采集、AI 分析的**完成时限**按任务类别单独定义，不能统一要求毫秒级。目标形态是先持久入队返回任务标识，再订阅/查询进度、结论和报告；每步执行时间、任务总超时、取消和失主恢复均受控。

兼容旧同步接口时，采用明确的异步入口或版本化契约迁移；不能静默把“报告响应”改成“接收回执”。查询要下推过滤、索引、分页和大小上限；模型推理、目标库慢查询及制品处理隔离到有界 worker。连接池、队列、并发、重试和日志均设上限，并为控制路径保留容量。

同时记录 P50/P95/P99、错误率、拒绝率、吞吐、排队与依赖耗时。5xx、超时、语义失败不能被剔除后宣称成功率或低时延；合法快速拒绝可以计入响应时延，但不能计作业务动作成功。另记真实端到端控制投递与停止确认时延。

## 5. 7×24 运行与故障恢复

连续运行指服务与受控任务的连续性，不要求单个进程永不退出。控制/API、调度、执行 worker、模型及采集进程隔离；单 worker、模型 OOM 或目标库故障不能拖垮全平台。资源配额、超时、熔断、退避、有界重试和队列背压是配套要求，不能只加全局 try/except。

- 服务与执行端由独立监督器管理，重启风暴须限频、告警并保持安全状态。存活、就绪和真实业务探针分别检测；不能让模型健康成为人工接管的前提。
- 任务、控制模式、owner/epoch、执行意图及审计可靠持久化；恢复后重新校验身份和授权，副作用结果不明时先对账，不自动重放。
- 高可用部署消除控制/API、入口、平台元库、任务状态与关键存储的单点；外置数据库仍须独立的 HA、备份和恢复演练，不能因“数据库外置”就假定没有单点。
- 数据库不可用或网络分区时，以一致性和安全为先停止新增高风险动作，保留明确降级与告警；磁盘满、文件描述符耗尽、OOM、慢依赖和备份失败均须覆盖。
- 二进制与 Docker 两种交付共用同一质量契约。更新先排空/冻结受影响任务，备份并执行可核对增量迁移，再切换、探针和复验；不可逆迁移或已有新写入时，不能简单替换旧程序并宣称可安全回滚。

建议服务目标：生产关键控制/查询服务按**自然月 99.99%**可用性验收草案推进（30 天约 4.32 分钟不可用预算）；计划升级造成的不可用也计入，除非交付合同另有明确约定。这不是“允许制造故障”，也不是当前承诺。以外部业务探针和真实请求统计，不能只看进程或 /health 返回值。

在平台元库及关键存储仍可用的**单应用节点故障**场景，建议恢复目标 `RTO <= 30 秒`；已确认任务/控制元数据以 `RPO=0` 为目标，需要相应持久化/复制协议与故障实验证据，不能由数据库单次 commit 推导任意故障下不丢数据。这些目标不套用到客户业务库恢复、整站断电或全部副本损坏，后者必须另定恢复与接管方案。

发布前至少做 **168 小时**目标负载长稳，覆盖正常峰值、过载保护、任务取消、模型不可用、进程退出、平台库故障和磁盘满等经过授权的演练。采集延迟、队列积压、内存、线程、连接与 FD 在事先冻结的资源预算内保持有界，结果/审计一致；压测和故障注入只在获准隔离环境执行。本轮未启动任何演练。

## 6. 当前差距与建设顺序

2026-10-20 仅复核下列入口与相关台账，不是新一轮全仓审计。当前分支 `codex/menu-optimization`，HEAD `a904301`；存在大量并行未提交工作，代码实际以本轮读取的工作区为准。

| 当前依据 | 本轮核实 | 到四项底线的差距 |
| --- | --- | --- |
| [巡检派发](../../backend/app/services/inspection/dispatch.py) `run_through_queue`、[持久任务](../../backend/app/services/inspection/jobs.py) `submit`/`execute`/`commit_results` | 已经经过持久队列，具备局部 owner/租约/取消门禁，不能继续笼统说“队列完全未接” | 交互路径仍内联等待执行结束；需真正的异步 worker 与接收回执，实测取消、任务隔离及性能 |
| [自动化服务](../../backend/app/automation/service.py) `cancel`/`_execute_executor` | 有取消标志，只有声明 cancel_check 的执行器收到检查回调 | 统一控制权/epoch、步骤安全点、所有适配器的停止确认和断网预算未验收；关联 ISS-31/ISS-32 |
| [内核采集服务](../../backend/app/kernel_observability/service.py) `set_kill_switch`、[现场重建服务](../../backend/app/scene_reconstruction/service.py) `cancel_capture_job` | 有局部急停和取消命令；不能当成全平台强制接管 | 命令入队不等于远端已停止，仍需统一投递/确认协议与独立控制容量 |
| [主调度](../../backend/app/tasks/master_scheduler.py) `run_due_tasks` | 有派发租约、epoch 和前后校验 | 不能推导在途外部副作用已停止；ISS-31 全链所有权仍开放 |
| [服务入口](../../backend/app/main.py) 的存活/就绪检查、[版本交付设计](../operations/release-lifecycle.md) | 有健康路径和交付底座 | 本轮未验证节点冗余、月可用率、RTO/RPO、毫秒长尾或 168 小时长稳，不宣称 Q03/Q04 达标 |

问题事实与状态沿用[已知问题台账](../known-issues.md)，不因本契约重复新建缺陷编号。建设顺序为：

1. **先补正确性和控制底座**：全链 owner/epoch、明确停止确认、目标/授权复核、在途副作用对账；高风险能力先保持阻断。
2. **再分离快慢路径**：接入独立有界 worker，控制面留保留容量；保留同步兼容，新增异步契约和真实排队/执行进度。
3. **随后完成稳定运行保障**：故障隔离、元库/控制面 HA、恢复与升级规程，先做授权故障矩阵，再做 168 小时长稳。
4. **按负载包实测并冻结指标**：覆盖正常、峰值、过载和故障情形，每条路径分别判定；未达标的能力不得计入自主执行范围。

交付证据必须注明版本/制品哈希、配置、环境与负载包、观测边界、原始结果位置、失败项及责任人。源码、隔离测试、CI、制品、部署和现场验收分栏记录，历史回归数量不替代当前性能、接管或长稳验收。

本轮只新增质量契约及蓝图引用，没有修改业务代码、生产参数、API 或表结构，没有调用现场数据库/模型/Agent，没有重启、压测、故障注入、部署或提交；也不改变 F01-F27 完成度。

本轮文档链接/锚点、正文路径、括号平衡、能力目录引用与 diff 格式检查通过；这些检查只证明文档和引用一致，不证明四项运行指标达标。用户要求与适用边界的摘要已于 2026-10-20 归档到指定个人知识库，并与归档稿逐字节核对一致。
