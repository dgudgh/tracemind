# Engine Secret Broker (EP-T04.W3, Unix development cell)

Verified on 2026-10-27 with test only credentials and local subprocesses. This is a Host owned credential broker for a signed, trusted Provider. It does not make Provider code a sandbox, revoke a database password already delivered into Provider memory, close server side database sessions, or undo a committed effect. The Windows named pipe cell and real DB driver cells remain separate work.

## Host integration contract

Create `SecretBroker(absolute_private_workdir, authorize=..., resolve_secret=..., on_close_request=..., on_terminate=...)` in the Host process and call `start()`. The root is owned by the Host UID with mode 0700; its short UDS path has mode 0600. Broker metadata SQLite is mode 0600 and contains only hashed lease/launch IDs, states, timestamps, fixed transition codes, and bounded denial codes with peer PID. On startup, rows left active or issued by a prior Host are marked revoked. Secret values and `secret_ref` exist only in Host memory; `resolve_secret` must query the platform vault directly, never an `.env` file. Avoid writing callback arguments or results to logs.

For each verified child launch, generate a fresh 32 byte `channel_key`. Call `register_launch({**vars(record), 'engine_id': engine_id}, channel_key=channel_key)` directly from Host Python. Registration verifies OS PID, UID, parent Host PID, process start time, and process group identity. Include only `{'broker_path': str(broker.path), 'broker_pid': os.getpid(), 'broker_key': channel_key.hex()}` under `secret_broker` in the protected inherited launch FD config. Never put this key in argv, ordinary environment, manifest, package, DB, or logs. Each Provider launch needs a distinct key.

`grant(secret_ref, {'id': principal_id, ...}, sdk_request_context, ttl_seconds)` returns an opaque lease ID. Host puts only this ID in operation params. `ttl_seconds` must be positive and no more than 60 seconds or the remaining absolute deadline. The broker derives purpose from the standard `capability_id`, target from `target_digest`, and binds engine/package/runtime/launch/operation/fence/deadline/scope. `authorize(principal, broker_context, phase)` must return `{'scope': allowed_scope_dict}` on grant, redeem and periodic monitor checks. The requested scope must be a nonempty subset. Callback failure rejects authorization. `resolve_secret(secret_ref, principal, broker_context)` returns a bounded JSON dictionary only at redemption; secret refs never reach Provider.

The signed SDK package must include `engine_sdk/broker_client.py` alongside `wire.py`; its relative `from . import wire` import allows the copied package to use it. In the Provider, use `BrokerClient.from_launch_config(config)`, then `client.redeem(lease_id, sdk_context)` to obtain the secret dictionary in memory. After closing every target connection or pool using the credential, call `client.release(lease_id, sdk_context)` in `finally`. Do not put returned secrets in results, plans, logs, persistent Provider state, or child process arguments. The client maps `capability_id` to broker purpose without adding it to the strict standard RPC context. A lease is redeemable once; another operation, target, scope, launch or OS PID cannot replay it.

## Native read Provider route

`build_provider_package(root, engine_id=..., private_key=..., trusted_key=..., synthetic_driver_source=...)` copies fixed official `app.engine_providers` source slices into a signed, self-contained `adapter_sources` directory. `build_extension_package(root, engine_id=..., adapter_source=..., driver=..., operations=..., private_key=..., trusted_key=...)` signs an external adapter at the same fixed `engine_provider.py` path. Both builders accept caller-owned in-memory test signing keys. `fixture_only=true` means a synthetic driver was included or an explicit development fixture was requested; the test signature channel alone does not imply synthetic runtime behavior. Every package defaults to `server_certified=false`. Official engine IDs require publisher `tracemind`; an extension ID is authorized by its current trusted key's publisher and engine scope. The signed `provider_profile` declares one fixed adapter file/hash, driver and read operations. Host rechecks signature, source inventory, adapter hash, ABI and runtime digest after staging; the SDK checks the loaded adapter's declared engine, driver, operations and version against the signed manifest. No business request can choose a module or executable. A synthetic DBAPI module is allowed only as a signed test payload and is never evidence of real driver certification. `FixtureSupervisor` still rejects native/extension packages. Server certification comes from external acceptance policy, never package self-report.

`ProviderSupervisor(broker=..., asset_resolver=..., workdir=...)` starts the fixed SDK launcher in a separate process and registers the actual child LaunchRecord before writing the protected FD config. `asset_resolver(asset_id, operation)` must return Host-frozen `target_digest`, `policy_digest`, nonempty `scope`, current `fence_epoch`, `principal`, and `secret_ref`. It must perform asset authorization; none of these facts are accepted from business RPC params. The broker's `resolve_secret` callback returns exactly `{'config': DBAPI_connect_kwargs, 'expected_identity': immutable_asset_identity}`. Only this redemption gives the Provider DB configuration and expected identity. `invoke_read(asset_id, operation, arguments={})` signs the operation and passes only `{operation, arguments, lease_id}` in RPC params. Nonempty arguments, raw SQL, config, passwords, arbitrary code paths, and write methods are rejected. The SDK calls the packaged `ReadProvider.invoke`, whose `finally` closes the DB cursor and connection, then acknowledges broker release. `selftest` checks the fixed Provider engine/version and named driver presence without a database connection. Missing driver prevents readiness. Actual DB identity is checked independently on every read by the packaged source adapter.

For explicit quarantine, permission/credential revocation, or invalid fence, call `revoke(lease_id=..., reason='credential_revoked')` or `revoke(launch_instance_id=..., reason='fence_invalid')`. The broker stops future redemption, dispatches `on_close_request(launch_id, reason)` for redeemed leases, and after a grace period invokes `on_terminate(launch_id, 'lease_revocation_unacknowledged')` if Provider did not acknowledge connection closure with `release`. The Host callback must match the original LaunchRecord process identity again before signaling its process group. Broker callbacks are dispatched on daemon threads so stalled Provider cleanup cannot block broker monitoring. Routine V→V+1 routing changes must not revoke a pinned old task's lease.

If effect or target session state is uncertain after termination, persist `effect_state=unknown` in the Host transaction state and run the normal verify/reconcile path. TTL expiration limits further broker authorization; it is not database password invalidation. A database administrator may still need to revoke an account/password or terminate server sessions.

## Local verification

From the repository root:

```sh
.venv-mac-primary/bin/python -m pytest -q backend/tests/test_engine_secret_broker.py backend/tests/test_engine_provider_rpc.py
```

The broker test runs a real UDS and separate Python Provider processes. `test_engine_provider_rpc.py` adds signed, self-contained synthetic MySQL and `demo.engine` packages with generic Supervisor subprocesses. They check OS peer PID rejection despite the same UID and known test channel key, single redemption, operation/target/scope replay rejection, authorization recheck, metadata restart revocation, no test secret in SQLite/argv/env, invalid business credentials/raw SQL rejection, wrong engine rejection, driver absence blocking readiness, and noncooperative expiry quarantining a live worker. They never contact a real DB, SSH server, or model API. Real driver/OS cells, registry acceptance and production Host integration require separate verification.
